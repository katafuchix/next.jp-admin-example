## 広告データの自動同期（cron・初回だけ）

VPS の cron が1日2回（日本時間 11時・18時）`POST /api/ads/sync` を呼び、直近7日の広告・売上を取り直して上書きする
（媒体の概算値が後から確定値に変わるのを吸収するため）。同じ呼び出しで課金率を日次で記録する（`isPaid` は今の状態しか
無く後から遡れないので、**この cron を入れた日から**課金率の推移が溜まる）。認証情報が未設定の媒体は飛ばされる。

```bash
# 1. 合言葉（AD_SYNC_SECRET）を作って .env の末尾に足す。値は画面に出ない。既にあれば何もしない
cd /home/admin/dev/hapiken-admin
cp .env .env.bak-$(date +%Y%m%d)
grep -q '^AD_SYNC_SECRET=.' .env || printf '\nAD_SYNC_SECRET=%s\n' "$(openssl rand -hex 32)" >> .env
pm2 restart hapiken-admin --update-env && pm2 save
```

```bash
# 2. cron から呼ぶスクリプトを置く（合言葉は .env から読むので crontab には書かない）
cat > /home/admin/ad-sync.sh <<'EOF'
#!/bin/bash
# 広告・売上の取り込み（直近7日）と課金率の日次記録。結果は /home/admin/ad-sync.log に追記
cd /home/admin/dev/hapiken-admin || exit 1
SECRET=$(grep '^AD_SYNC_SECRET=' .env | tail -n 1 | cut -d= -f2-)
{
  echo "=== $(date '+%F %T %Z') ==="
  curl -sS -m 600 -X POST http://localhost:3001/admin/api/ads/sync -H "Authorization: Bearer $SECRET"
  echo
} >> /home/admin/ad-sync.log 2>&1
EOF
chmod 700 /home/admin/ad-sync.sh

# 3. 手で1回動かす。"success":true と "paidRate" が出れば成功（媒体は認証情報が届くまで "skipped" が正常）
/home/admin/ad-sync.sh && tail -n 2 /home/admin/ad-sync.log
```

```bash
# 4. サーバーの時間帯を確かめる（末尾が JST か UTC か）
date
```

```bash
# 5a. JST と出たとき（5b と両方は入れない）
(crontab -l 2>/dev/null; echo '0 11,18 * * * /home/admin/ad-sync.sh') | crontab - && crontab -l
```

```bash
# 5b. UTC と出たとき
(crontab -l 2>/dev/null; echo '0 2,9 * * * /home/admin/ad-sync.sh') | crontab - && crontab -l
```

| 項目 | 確認 |
| --- | --- |
| 動いたか | `tail -n 6 /home/admin/ad-sync.log`（11時・18時ごとに `===` の行が増える） |
| 401 が返る | `.env` に `AD_SYNC_SECRET` が無いか、足したあと `pm2 restart hapiken-admin --update-env` をしていない |
| 媒体の認証情報を足したとき | `.env` に追記 → `pm2 restart hapiken-admin --update-env` → 3 を手で1回。変数は [`02_環境変数リファレンス.md`](02_環境変数リファレンス.md) |
