# 既知の課題と残タスク

引き継ぎ後、新エンジニアが最初に着手すべき優先度つきリスト。上から順に対応することを推奨する。

## 1.【最優先・セキュリティ】`app/api/debug-env/route.ts` が認証なしで公開されている

`GET` ハンドラに `auth()` チェックが無く、`proxy.ts`（`matcher: []` で無効化済み）にも
`app/(dashboard)/layout.tsx` の認証ガード（API Routeには効かない）にも保護されていない。
本番で誰でも認証なしにこのエンドポイントへアクセスでき、以下が返る。

```ts
{
  ADMIN_MONGODB_URI: "set (starts with: mongodb+srv://...)",  // 先頭15文字が漏洩
  AUTH_SECRET: "set" | "NOT SET",
  NODE_ENV: "production"
}
```

**対応方針**: デバッグ用途が終わっているなら**エンドポイント自体を削除**する。残す必要がある場合は
`auth()` チェックを追加し管理者ロールのみアクセス可能にする。

## 2. `/ads` 画面の媒体ごとの取得処理が未実装（モックは撤去済み）

モックは撤去し、画面は取り込み済みの日次データ（`AdDailyStat`）を期間で集計して出すようになった。
対象は Tenjin / AdMob / AdGeneration / SmaAD / App Store Connect / Google Play の6媒体
（`lib/ad-sources/registry.ts`）。ただし各媒体の API から実際に取ってくる処理はまだ無く、
認証情報をそろえても同期結果は「取得処理がまだ実装されていません」の未取得になる。
取り込めていない媒体がある指標は、画面上で値の代わりに「未接続: 媒体名」と出るので、
架空の数字が経営判断に使われることはない。

**対応方針**: 認証情報を受け取った媒体から、実レスポンスの形を固定したテストを先に書いて
取得処理を足す。順番と確認方法は `tasks/todo.md` の Phase 2〜4。

## 3.【最優先】`FIREBASE_SERVICE_ACCOUNT_KEY` が本番の両`.env`に未設定

現在プッシュ通知は mock 送信フォールバックで動作しており、DBには「送信成功」として記録されるが
**実際には端末に届いていない**。

**対応手順**:
1. Firebaseコンソール > プロジェクトの設定 > サービスアカウント > 新しい秘密鍵を生成
2. 生成したJSONをbase64エンコード（`base64 -i key.json`）
3. `/home/admin/dev/hapiken-admin/.env` と `/home/admin/dev/care/.env` の両方に追記
4. `pm2 restart hapiken-admin` と `pm2 restart server` で反映（`--update-env` 付き）

## 4. iOSプッシュ通知未対応

ブロッカー連鎖: macOS 26.2+ → Xcode 17 → CocoaPods → `cap sync ios` → APNsキー取得
（Apple Developer Program）→ Firebaseにアップロード。Androidは対応済み。

## 5. Socket.IOオンライン判定の実地検証が未実施

実装・デプロイは完了しているが、本番環境での動作確認（複数タブ・複数端末・サーバー再起動時の
自己修復挙動など）がまだ行われていない。

## 6. nodemailerの依存衝突

`nodemailer@9.0.1` に対し `next-auth` が `^7` を要求しており、`npm install` 系コマンドで
ERESOLVE エラーが発生する（`pnpm install` では発生しない）。恒久対応は未実施。

## 7. `_archive_hapiken-admin/` の最終処分

重複クローンを退避したディレクトリ。中身は本体に取り込み済みと確認済みのため、
問題なければ削除してよい（`.gitignore` 済み・未追跡）。
