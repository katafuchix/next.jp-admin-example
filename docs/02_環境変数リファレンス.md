# 環境変数リファレンス

`env.example` をコピーして `.env` を作り、以下を参考に値を埋める。**値そのものはこのファイルにも
`env.example` にも書かない**（コミット対象外・`.gitignore` で除外済み）。

## データベース（MongoDB）

| 変数名 | 用途 | 必須/任意 | 未設定時の挙動 | 取得元・補足 |
|---|---|---|---|---|
| `ADMIN_MONGODB_URI` | 管理画面自身のデータ（Admin/AuditLog/Notification 等11モデル）用の接続文字列 | **必須** | `connectDB()`（`lib/db.ts`）が**例外を投げる**。起動不能 | MongoDB Atlas等のクラスタ管理画面。専用クラスタ推奨 |
| `APP_MONGODB_URI` | care（アプリ本体）が書き込む `users`/`healthlogs` コレクションへの読み取り専用接続 | 推奨（顧客管理・分析機能を使うなら実質必須） | `connectAppDB()` が **`null` を返す**（例外にはならずビルド・起動は通る）。顧客一覧・顧客分析・オンライン判定の画面が空表示になる | care チーム/インフラ担当から共有を受ける（care 本体と同じ MongoDB クラスタの接続情報） |

## 認証（NextAuth v5）

| 変数名 | 用途 | 必須/任意 | 未設定時の挙動 | 取得元・補足 |
|---|---|---|---|---|
| `AUTH_SECRET` | セッション（JWT）の暗号化キー | **必須** | NextAuth が正常に動作しない（署名検証不能） | `openssl rand -base64 32` で生成 |
| `AUTH_URL` | ログイン成功後のリダイレクト先ベースURL。**basePath `/admin` を含めること** | 本番は必須（ローカルは省略可） | `app/(auth)/actions.ts` の `redirectTo: process.env.AUTH_URL \|\| "/admin"` により、ローカルは相対パス `/admin` にフォールバックするため気づきにくいが、**本番で含め忘れると NextAuth が basePath なしの誤ったURLへリダイレクトする** | 例: 本番 `https://hapiken.jp/admin`、ローカル `http://localhost:3000/admin` |
| `AUTH_TRUST_HOST` | （設定不要）NextAuth のホスト検証を許可するフラグ | — | **`.env` に書いても無視される**。`auth.ts` と `next.config.ts` の両方でコード側から `"true"` に強制上書きされているため | 設定する必要はない。詳細は [`01_アーキテクチャ.md`](01_アーキテクチャ.md) |

## プッシュ通知（Firebase Admin SDK V1 / FCM）

| 変数名 | 用途 | 必須/任意 | 未設定時の挙動 | 取得元・補足 |
|---|---|---|---|---|
| `FIREBASE_SERVICE_ACCOUNT_KEY` | FCM送信用サービスアカウント鍵（JSONをBase64エンコードした文字列）。Firebase Storageアップロードにも同じ鍵を使用 | 任意・**ただし実質必須** | ⚠️ **エラーにならず「送信成功」としてDBに記録されるが、実際には端末に届かない（mock送信フォールバック）**。気づきにくい落とし穴。本番の現状値は未設定（[`04_既知の課題と残タスク.md`](04_既知の課題と残タスク.md) 参照） | Firebaseコンソール > プロジェクトの設定 > サービスアカウント > 新しい秘密鍵を生成 → JSONを `base64 -i key.json` 等でエンコード |

## 通知スケジュール配信（Cloud Scheduler）

単発予約・繰り返し配信の通知(`/notifications`)で使用。Cloud SchedulerのJob作成・更新・一時停止・削除は
`lib/scheduler.ts` が `FIREBASE_SERVICE_ACCOUNT_KEY` と同じサービスアカウントを使って行うため、
GCP側でそのサービスアカウントに `roles/cloudscheduler.admin` を追加付与しておくこと。詳細は
[`05_通知スケジュール配信.md`](05_通知スケジュール配信.md) を参照。

| 変数名 | 用途 | 必須/任意 | 未設定時の挙動 | 取得元・補足 |
|---|---|---|---|---|
| `GCP_SCHEDULER_LOCATION` | Cloud SchedulerのJobを作成するリージョン | 単発予約・繰り返し配信を使うなら必須 | 通知保存時に`syncSchedulerJob()`が例外を投げ、単発予約・繰り返し配信の作成/更新がエラーになる(即時配信には影響なし) | 例: `asia-northeast1` |
| `NOTIFICATION_DISPATCH_BASE_URL` | Cloud Schedulerが配信処理エンドポイント(`/api/notifications/dispatch/[id]`)を呼び出す際のベースURL | 同上 | 同上 | 本番は`AUTH_URL`と同じ値でよい(例: `https://hapiken.jp/admin`) |
| `NOTIFICATION_DISPATCH_SECRET` | Cloud Schedulerからの呼び出しを認証する共有シークレット。`/api/notifications/dispatch/[id]`が`Authorization: Bearer <値>`を検証する | 同上 | 未設定だとこのエンドポイントが常に401を返し、予約・繰り返し配信が一切配信されない | `openssl rand -base64 32` で生成 |

## 画像アップロード（キャンペーン画像 / Firebase Storage）

| 変数名 | 用途 | 必須/任意 | 未設定時の挙動 | 取得元・補足 |
|---|---|---|---|---|
| `FIREBASE_STORAGE_BUCKET` | キャンペーン画像アップロード先のFirebase Storageバケット名（`gs://<bucket>` 形式） | 任意・**ただし画像アップロード機能に実質必須** | ⚠️ 未設定だとキャンペーン画像アップロードAPIがエラーになる（他の機能には影響なし） | Firebaseコンソール > Storage > 利用開始（リージョン: asia-northeast1）→ 有効化後に表示されるバケット名をそのまま貼り付け |

## メール送信（問い合わせ返信・メルマガ配信）

| 変数名 | 用途 | 必須/任意 | 未設定時の挙動 | 取得元・補足 |
|---|---|---|---|---|
| `SMTP_HOST` | SMTPサーバーホスト名 | 任意（メール送信機能を使うなら必須） | 6変数のいずれか未設定でもビルド・起動は通るが、メール送信系機能（問い合わせ返信・メルマガ配信）が動作しない | 利用するSMTPプロバイダの管理画面（例: SendGrid） |
| `SMTP_PORT` | SMTPポート番号 | 同上 | 同上 | 通常 `587`（STARTTLS） |
| `SMTP_SECURE` | `"true"` でSMTPS(465番)。587番STARTTLSの場合は `"false"` のまま | 同上 | 同上 | プロバイダの推奨設定に従う |
| `SMTP_USER` | SMTP認証ユーザー名 | 同上 | 同上 | 例: SendGridは固定文字列 `apikey` |
| `SMTP_PASS` | SMTP認証パスワード/APIキー | 同上 | 同上 | プロバイダ発行のAPIキー |
| `SMTP_FROM` | 送信元メールアドレス | 同上 | 同上 | 独自ドメインの送信元アドレス |

## 広告媒体レポート連携

`POST /api/ads/sync`（`lib/ad-sync.ts`）が、媒体ごとに下の変数が**全部そろったものだけ**を取り込む。
1つでも欠けている媒体は「未接続」として飛ばし（`status: "skipped"`）、`/ads`・`/revenue` は値の代わりに
「未接続」と出す。媒体と必須変数の定義は `lib/ad-sources/registry.ts`。
取得処理が実装済みなのは Tenjin・AdMob（Tenjin 経由）・AdGeneration・App Store Connect・Google Play・SmaAD（広告出稿）。
SmaAD（広告出稿）は変数がそろうまで同期に含めず、管理画面の CSV を画面から取り込む（そろえば API の値で上書きする）。SmaAD（オファーウォールの収益）は API が見つかっていないので CSV の取り込みだけ。

| 変数名 | 用途 | 必須/任意 | 未設定時の挙動 | 取得元・補足 |
|---|---|---|---|---|
| `AD_SYNC_SECRET` | VPS の cron が `POST /api/ads/sync` を呼ぶときの `Authorization: Bearer <値>` | 自動同期を使うなら必須 | cron からの呼び出しが全部401になり、自動同期と課金率の日次記録が止まる（画面の「今すぐ同期」はログイン＋書き込みロールで動くので影響なし） | `openssl rand -hex 32` で生成。cron の設定は [`03_本番反映手順.md`](03_本番反映手順.md) |
| `TENJIN_API_KEY` | Tenjin（広告経由のインストール数。広告費は取り込まない。広告費は SmaAD の広告出稿から取る） | 任意 | Tenjin を未接続として飛ばす | Tenjin の管理画面 |
| `ADMOB_CLIENT_ID` | Google AdMob（広告収益）の OAuth クライアントID | 任意（4つそろって有効） | AdMob を未接続として飛ばす | Google Cloud Console |
| `ADMOB_CLIENT_SECRET` | 同上のシークレット | 同上 | 同上 | 同上 |
| `ADMOB_REFRESH_TOKEN` | 同上のリフレッシュトークン | 同上 | 同上 | OAuth の承認で発行 |
| `ADMOB_PUBLISHER_ID` | AdMob のパブリッシャーID（`pub-...`） | 同上 | 同上 | AdMob 管理画面。アカウントの「レポートの時間帯」が日本時間でないと取り込まず失敗にする |
| `ADGENERATION_EMAIL` | AdGeneration（広告の参考収益・表示回数・クリック数）にログインするユーザーのメールアドレス | 任意（2つそろって有効） | AdGeneration を未接続として飛ばす | AdGeneration 管理画面 > ユーザー一覧で取り込み専用のユーザーを作る（API キーは無い。同期のたびに10分有効のトークンを発行する） |
| `ADGENERATION_PASSWORD` | 同上のパスワード | 同上 | 同上 | 同上 |
| `SMAAD_ADVERTISER_API_KEY` | SmaAD（広告出稿）の広告主向け Report API のキー。広告費（円）・表示回数・クリック数・成果件数を日別に取る | 任意（2つそろって有効） | 同期に含めず、CSV の取り込みだけで動く | SmaAD の営業担当（GMO TECH）から受け取る。キーは URL に載るので、URL をログやチャットに貼らない |
| `SMAAD_ADVERTISER_ACCOUNT_ID` | 同上の広告主アカウント ID（数字） | 同上 | 同上 | 同上 |
| `APPSTORE_ISSUER_ID` | App Store Connect API の Issuer ID | 任意（4つそろって有効） | App Store Connect を未接続として飛ばす | App Store Connect > ユーザとアクセス > 統合 |
| `APPSTORE_KEY_ID` | 同上の Key ID | 同上 | 同上 | 同上 |
| `APPSTORE_PRIVATE_KEY` | 同上の API キー（.p8）の中身。1行にする場合は改行を `\n` で書く | 同上 | 同上 | 同上（.p8 は発行時に1回しかダウンロードできない） |
| `APPSTORE_VENDOR_NUMBER` | 売上レポートのベンダー番号 | 同上 | 同上 | App Store Connect > 支払いと財務レポート |
| `GOOGLE_PLAY_SERVICE_ACCOUNT_JSON` | Google Play の売上レポートを読むサービスアカウントJSON。`FIREBASE_SERVICE_ACCOUNT_KEY` とは別物 | 任意（2つそろって有効） | Google Play を未接続として飛ばす | Google Cloud Console（Play Console で財務データ閲覧権限を付ける） |
| `GOOGLE_PLAY_REPORTS_BUCKET` | レポートの保管先バケット（例: `pubsite_prod_rev_01234567890987654321`） | 同上 | 同上 | Play Console > ダウンロード レポート |
