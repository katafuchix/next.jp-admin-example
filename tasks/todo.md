## 要件（先方原文の要約）

## 調べて分かったこと（2026-09-23）

- 広告データ画面 `/ads` と `lib/ad-sync.ts` は**全部モック**。しかも媒体が Meta / Unity / AppLovin で、今回の6媒体と合っていない
- 収支分析 `/revenue` が読む `RevenueData` は**書き込む処理がどこにも無い**（本番は空のはず）
- DB は2本。管理画面DB（`ADMIN_MONGODB_URI`・読み書き）と、アプリDB（`APP_MONGODB_URI`・設計上は読み取り専用）
- アプリ（care）は **ホーム画面を開くたびに `dashboardstats` へ「ユーザー×日付（JST）」の行を1本作る**（`server/routes/dashboard.ts:438`、一意キー `userId+date`）。これで DAU/WAU/MAU/リテンションが**過去分まで**出せる見込み
- 退会は `DELETE /api/user/profile` の**物理削除**（`server/routes/user.ts:490`）。記録が残らないので、**退会数は記録を入れた日以降しか数えられない**
- アプリ内の広告: バナー = AdMob、リワード（ガチャ・AI解放）= AdGeneration、オファーウォール = SmaAD（GMO TECH）。計測 SDK は Tenjin（iOS/Android とも導入済み）

- 07-21 に AdGeneration / Tenjin の取込（Googleスプレッドシート経由）を **care/admin（使われていない残骸）** に実装していた（`b30d02d`）。項目設計（概算10時→確定17時を同じキーで上書き）は流用できる

## 指標の定義（前提・確認が取れていないので仮置き）

- **アクティブ** = その日（JST）にアプリのホーム画面を開いたユーザー（`dashboardstats` に行がある）
- **DAU** = 日ごとのアクティブ数 ／ **WAU・MAU** = 直近7日・30日のユニーク数
- **リテンション率** = 登録日ごとの D1 / D7 / D30 継続率（登録後N日目にアクティブだった割合）
- **総ログイン数** = 期間内の延べアクティブ日数（1人1日1回）。起動回数そのものは記録が無い
- **課金率** = 課金中ユーザー ÷ 総ユーザー。`isPaid` は今の状態しか無いので、**推移は日次の記録を始めた日から**
- **ARPU** = 期間の総収益（課金＋広告）÷ 期間のアクティブユーザー（ユニーク）
- **ARPPU** = 期間の課金収益 ÷ 課金ユーザー数 ／ **ARPDAU** = 日次の総収益 ÷ DAU
- **広告費** = Tenjin の出稿費 ／ **CPI** = 広告費 ÷ 広告経由インストール数
- **ROAS** = 期間の総収益 ÷ 広告費 ／ **ROI** =（総収益 − 広告費）÷ 広告費。期間ベース（登録コホート別ではない）
- **金額** = 円。課金はストア手数料を引いた**手取り**で計算し、税込売上も保存しておく（後から切替可能）
- **インストール曜日・時間帯** = アプリの**新規登録日時**で代用。Tenjin の端末ごとのインストール時刻は有料オプション（DataVault）が要る
- **退会ユーザー数** = care に退会の記録を追加した日以降の件数
- **保存先** = 取得データは**管理画面DB**に置く。アプリDBは読み取り専用の設計なので書かない（先方の「アプリDBへ連携」はこの意味と解釈）
- **同期** = VPS の cron から毎日2回（11時・18時 JST）、直近7日を取り直して上書き（概算→確定値の差し替えを吸収）。管理画面から手動同期も可
- 同期に失敗したらモックで埋めず「失敗」と画面に出す
